# 有戴耳機才開口，沒戴就退回一般通知

- **狀態：** 💭 發想中
- **日期：** 2026-10-10

**想法：** Rorty 主動用語音找我時，先偵測手機有沒有接耳機。有接就直接說話；沒接就不出聲，改發一般的文字通知。

**為什麼想做：** 語音的目的是主動把我的注意力搶過來，不用我點開 app。但如果沒戴耳機時直接從喇叭播出來，在辦公室或捷運上會很尷尬，內容也可能被旁邊的人聽到。只要發生一兩次，我就會想把語音整個關掉，反而失去這個專案最初的發想。

**要大改嗎？** 不用，只在手機端的原生服務裡**多一個判斷**：
- `server/` 完全不用動，照樣發 FCM 高優先資料訊息。
- `mobile/android/` 的原生服務在播放語音前，先檢查音訊輸出裝置。
- Angular 那層不用動（app 沒開時它本來就不會執行）。

### 流程

```
收到 FCM 資料訊息
        ↓
   有接耳機嗎？
   ├─ 有 → 啟動前景服務 → 播放語音
   └─ 沒有 → 顯示一般通知（文字）
```

### 判斷方式

用 Android 的 `AudioManager.getDevices()` 查目前的輸出裝置，以下任一種存在就算「有戴耳機」：

| 類型 | 說明 |
|---|---|
| 藍牙耳機 | A2DP、BLE 耳機 |
| 有線耳機 | 3.5mm、USB-C |

### 一起處理的相關狀況

| 狀況 | 處理方式 |
|---|---|
| 媒體音量為零 | 語音走媒體音量，為零時聽不到，一樣退回一般通知 |
| 正在聽音樂 | 向系統要求暫時壓低音樂音量，說完再恢復，像導航語音那樣 |
| 耳機接著但沒戴在耳朵上 | 手機偵測不到，先接受這個限制 |

### 還沒想清楚的

- 藍牙喇叭、車用藍牙要算「耳機」嗎？在家或車上其實適合出聲，但偵測結果和耳機很像。
- 退回文字通知後，之後戴上耳機要不要補播？
- 要不要讓很重要的訊息可以無視這個規則直接出聲？
