# 讓 Rorty 主動開口，像朋友一樣來找我

- **狀態：** 💭 發想中
- **日期：** 2026-09-30

**想法：** 現在 Rorty 只有在我打指令時才說話。希望它能自己醒來、判斷現在適不適合找我，需要時主動開口，最後透過耳機跟我說話。

**為什麼想做：** 這是「夥伴」和「工具」的差別。我不一定會記得去找它，尤其是最需要提醒的時候（例如遊戲玩太久、好幾天沒打卡）。它主動來找我，才像一起床就在身邊的朋友。

**要大改嗎？** 不用，只要**新增**東西：
- `hello` 指令其實就是 Rorty 主動開口的「聲音」，只是現在要等我按下去。
- `memory.py` 加一張 `nudges` 表、兩個方法就好。
- `persona.md`、既有的 `chat` / `checkin` / `review` 都不用動。

### 拆成三個零件

| 零件 | 要回答的問題 | 做法 |
|---|---|---|
| **觸發** | 什麼時候醒來？ | 先用 Windows 工作排程器每 30～60 分鐘跑一次 `nudge`，加一個固定的晨間招呼；之後再加事件觸發（遊戲開超過 90 分鐘、今天還沒打卡、行程快到了） |
| **判斷** | 該不該說？說什麼？ | 讓 Claude 看完情境後回傳 `{ speak, reason, message }`，而不是直接產生一段話；判斷用 Haiku，心跳頻繁也不貴 |
| **管道** | 怎麼傳到我耳邊？ | 桌面通知 → Telegram bot → 耳機語音，一路升級 |

### 要特別處理的是「沉默」

醒來不等於要說話，**預設應該是沉默**。不然很快就會變成我想關掉的通知。

判斷時餵給模型的情境：現在時間、上次打卡內容、`me.md` 裡的提醒偏好、最近幾次主動找我的紀錄。

另外加幾條**寫死的硬規則**，不交給模型決定：
1. **安靜時段**：例如 23:00–08:00 不打擾
2. **冷卻時間**：兩次主動開口至少間隔 N 小時
3. **每日上限**：一天最多 N 次

`nudges` 表會記錄每次開口的時間、內容、我有沒有回應，之後 Rorty 就能學到「哪種提醒她會理、哪種她會忽略」。

真正決定 Rorty 像朋友還是像煩人鬧鐘的，是這一層，不是觸發和管道。

### 管道的升級路線

1. **桌面通知**：開發期最快，今天就能做（FastAPI 跑在 Windows 主機上，本機 `notify` 跳通知）。
2. **自己的 app 推播**：後端呼叫推播服務（FCM），把 `nudge` 的內容送到 Capacitor app。Phase 1 的 Ionic + Angular 聊天頁，之後直接拿來當推播的接收介面，點開通知就能回話
3. **App 內語音播放**：推播送出前，後端先用 `edge-tts`（台灣中文聲音，例如 `zh-TW-HsiaoChenNeural`）把要說的話轉成音檔，網址放進推播 payload；app 收到推播就自動下載播放，不用先點開 app。藍牙耳機連著，一樣是「它在耳邊跟我說話」，只是聲音是從手機 app 播出來，不是從 Windows 主機。

### 預計的改動

```
app/main.py      ← 加 nudge 指令：組情境 → 模型判斷 → 套硬規則 → 決定要不要說
app/memory.py    ← 加 nudges 表 + add_nudge() / recent_nudges()
app/notify.py    ← 新增：送出管道（先做桌面通知；Phase 1 app 做出來後，改成呼叫 FCM 推播 + 帶 edge-tts 音檔網址）
app/tts.py       ← 新增（Phase 3 提前一部分）：把 nudge 要說的話轉成語音檔，給推播 payload 用
app（Angular + Capacitor）← 接收推播、自動播放語音；沒有獨立的 app 之前，這一步做不了，只能先停在桌面通知
```

### 跟 roadmap 的關係

這是「會主動找我」這條路線的起點。之後的遊戲時間提醒、活動推薦、定期回顧，都會透過同一個 `nudge` 判斷層和 `notify.py` 送出，不用各自再做一套。
